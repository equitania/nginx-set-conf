# RELEASE NOTES

## Version 1.10.0 (21.04.2026)

### Fixed (Availability)
- **[FIX]** Remove hostname from `listen` directives in all 17 templates to eliminate
  nginx startup failures on transient DNS resolver glitches.
  - Before: `listen server.domain.de:80;` → nginx must resolve the hostname at
    config-parse time on every reload/restart. Upstream DNS hiccups caused
    `[emerg] host not found in "..." of the "listen" directive` and took down
    all vhosts on the machine.
  - After: `listen 80;` / `listen 443 ssl;` — nginx binds to the port on all
    interfaces, vhost routing happens via `server_name` at request time (HTTP
    Host header / SNI), no DNS lookup during config parse.
  - This restores the fix that was introduced in `af81437` (2024-12-06) and
    accidentally reverted in `08d592a` (2024-12-10).
- **[FIX]** `retrieve_valid_input` (utils.py) rewritten as a loop instead of
  recursive self-call, preventing `RecursionError` on pipelined empty input.

### Security / CI
- **[CHG]** CI workflow: remove `continue-on-error: true` on the mypy step so
  type regressions actually fail the build.
- **[CHG]** CI workflow: remove `-ll` flag from the bandit scan so LOW-severity
  findings are reported (and can be addressed or explicitly suppressed).
- **[ADD]** CI workflow: explicit `permissions: contents: read` at workflow and
  job level to minimise GitHub token scope.

### Deprecated
- **[CHG]** `--disable_domain_listen` CLI flag is now a no-op (kept for backward
  compatibility with existing YAML configs and wrapper scripts). The flag
  previously stripped hostnames from `listen` directives; this is now the
  default behaviour.

### Migration Notes
- Existing nginx configs generated by earlier versions (with hostnames in
  `listen` directives) continue to work. Servers with manually `sed`-patched
  configs (IP-based listen directives) will be cleanly migrated to `listen 80;`
  when the config is regenerated via `nginx-set-conf` — no manual rescue
  operations required after the Tool update.
- Regenerate configs after upgrading:
  `nginx-set-conf --config_path=/path/to/yaml-config && systemctl reload nginx`

### Tests
- **[ADD]** Regression test `test_no_hostname_in_listen_directive` ensuring no
  template ever re-introduces a hostname-bound `listen` directive.
