# Roadmap: nginx-set-conf v1.12

## Overview

v1.12 closes out every MEDIUM and LOW concern surfaced in the
2026-05-28 codebase audit (`.planning/codebase/CONCERNS.md`), plus
the two open questions raised in the same audit. No new operator-
facing CLI flags; behavioural changes are limited to validator
tightening and template cleanup. Each phase ships independently
and ends with a green test suite + a `bump-my-version`-managed
release candidate. The goal is to enter v1.13 with a near-empty
CONCERNS.md so the next minor can resume feature work.

## Phases

**Phase Numbering:**
- Integer phases (1, 2, 3, 4): Planned hardening work
- Decimal phases reserved for urgent insertions during execution

- [ ] **Phase 1: Privileged write-surface hardening** — Close the four
      MEDIUM/LOW security gaps that let a hostile YAML or stale
      filesystem state reach the host.
- [ ] **Phase 2: Cache + template substitution consolidation** — Reduce
      the dual cache-path pipeline to one source of truth and make
      sentinel values explicit.
- [ ] **Phase 3: Tech debt + repository cleanup** — Retire the
      deprecated `config_templates.py` shim, remove committed build
      artefacts, slim down the redirect templates.
- [ ] **Phase 4: Docs, open questions, release** — Fix documentation
      drift, resolve the two open questions from the audit, ship
      v1.12.0.

## Phase Details

### Phase 1: Privileged write-surface hardening
**Goal**: Every input that could expand the tool's reach on the host
filesystem — YAML `target_path`, backup symlink behaviour, the
self-signed key file, interactive stdin — passes a tighter validator
or a safer write pattern.
**Depends on**: Nothing (first phase after v1.11.1)
**Requirements**: SEC-01, SEC-02, SEC-03, SEC-04
**Success Criteria** (what must be TRUE):
  1. A YAML config supplying `target_path: "  ../etc"` is rejected by
     `validate_target_path` with a clear error.
  2. `backup_configuration` refuses to follow a symlinked source
     directory and copies without following symlinks in the source
     tree.
  3. The private key generated by `setup_default_server` is mode
     `0o600` at every observable moment between creation and the
     `chmod` call (verified by inspecting the post-condition or by a
     `umask`-guarded openssl invocation).
  4. A piped 100 KB stdin to the interactive prompt does not exhaust
     the recursion stack; the input is bounded by an explicit length
     cap.
  5. Full test suite green; coverage gate (60%) still met.

- [ ] 01-02: SEC-02 copytree symlink safety

### Phase 2: Cache + template substitution consolidation
**Goal**: One authoritative pass rewrites cache paths from a single
sentinel. Redirect templates can no longer leak their literal
`target.domain.de` sentinel into nginx log file paths.
**Depends on**: Phase 1
**Requirements**: COR-01, COR-02, COR-03, COR-04, COR-05
**Success Criteria** (what must be TRUE):
  1. `all_templates.py` no longer pre-substitutes `proxy_cache_path`;
     `utils.py` is the single authoritative substitution site and
     produces identical output to the previous pipeline (verified by
     existing template tests).
  2. A `redirect` / `redirect_ssl` invocation without
     `--redirect_domain` fails validation before any file is written.
  3. `CACHE_PATH_SENTINEL` is defined once and imported by every
     template + `all_templates.py`. No magic `/tmp` literal remains.
  4. The status of `default_ssl_reject` in `VALID_TEMPLATES` is
     either explicit (whitelisted + documented) or its exclusion is
     justified inline at `validators.py:25-43`.
  5. Cache-path regex uses a `lambda` `repl` instead of an
     `f"\\1..."` back-reference; output unchanged for existing
     domains.
  6. Full test suite green; no template output diffs except the
     intentional changes (verified by golden-output tests if
     present, otherwise by manual review of `test_templates.py`).

### Phase 3: Tech debt + repository cleanup
**Goal**: The repository checkout matches a clean build. The
deprecated import path is gone. Stale committed artefacts are
removed. Redirect templates carry only what they actually use.
**Depends on**: Phase 2
**Requirements**: TD-01, TD-02, TD-03, TD-04, TD-05, TD-06
**Success Criteria** (what must be TRUE):
  1. `nginx_set_conf_equitania.egg-info/` no longer exists in the
     working tree or in git.
  2. `config_templates.py` is removed. `nginx_set_conf.py` imports
     `get_config_template` (or equivalent) from `all_templates`. No
     `print()` side-effects on template fetch.
  3. `nginx_set_conf.log` is no longer tracked by git
     (`git ls-files` returns nothing for it).
  4. `build/` and `dist/` are confirmed gitignored and untracked.
  5. `templates/redirect.py` and `templates/redirect_ssl.py` have no
     `proxy_cache_path` or `limit_req_zone` directives. `nginx -t`
     accepts the generated configs (verified by manual server-side
     check during release).
  6. The interactive CLI path either prompts for `cert_key` or the
     Let's-Encrypt-only behaviour is documented in `--help`.
  7. Full test suite green.

### Phase 4: Docs, open questions, release
**Goal**: Documentation matches reality. The two open questions from
the audit have a recorded decision and a shipped implementation
(or a documented manual procedure). v1.12.0 is tagged and pushed.
**Depends on**: Phase 3
**Requirements**: DOC-01, Q-01, Q-02
**Success Criteria** (what must be TRUE):
  1. `CLAUDE.md` correctly states that `replace_cache_path` lives in
     `nginx_set_conf/templates/all_templates.py`.
  2. Q-01 has a documented decision in `RELEASE_NOTES.md` v1.12 — either
     `--migrate_to_ip_bound` is implemented with rollback semantics
     analogous to `--migrate_to_wildcard`, or the teaser is removed
     from RELEASE_NOTES.md and the manual migration procedure is
     documented in README.md.
  3. Q-02 has a documented decision — either `--force` is added to
     `--sync_config` with a pre-sync warning that operator-local
     customisations will be lost, or the limitation is documented
     prominently in README.md.
  4. `CONCERNS.md` is re-audited after Phases 1–4 land — the count of
     HIGH/MEDIUM findings is zero. LOW findings, if any remain,
     have a justified deferral note.
  5. `bump-my-version bump minor` succeeds; tag `v1.12.0` is pushed
     to `origin` and `upstream`; PyPI publish completes locally.
