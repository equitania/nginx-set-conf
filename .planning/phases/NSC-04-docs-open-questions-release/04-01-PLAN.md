## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → sync_configurations | --force flag controls destructive server-file overwrite; without it the operation aborts |
| embedded template → /etc/nginx/ | sync writes tool-managed content to privileged nginx directories (same boundary as before; now gated) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | sync_configurations / _perform_sync | mitigate | --force gate: without explicit flag, method aborts before any write; operator must pass --force consciously, preventing accidental destruction of operator-local nginx customisations |
| T-04-02 | Information Disclosure | CLAUDE.md / README.md doc changes | accept | Documentation corrections expose no secrets; low-value target |
| T-04-03 | Tampering | RELEASE_NOTES.md edits | accept | RELEASE_NOTES is a text file in version control; no executable surface |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | This plan introduces no new package dependencies; no package manager installs occur |

Note: The --force gate directly addresses the data-loss risk identified in CONCERNS.md §Q-2. Threat T-04-01 is the primary security-relevant change in this plan.
</threat_model>
