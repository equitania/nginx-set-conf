# Phase 2.5: HTTP/2 actually enabled — Context

**Gathered:** 2026-05-28
**Status:** Ready for planning
**Source:** `/gsd:discuss-phase --all` (HTTP/3 review surfaced this gap)

<domain>
## Phase Boundary

Phase 2.5 makes the long-standing `# incl. SSL/http2` banner truthful.
Every per-service SSL template and the embedded `NGINX_CONF_TEMPLATE`
currently advertise HTTP/2 in their version comments but emit no
`http2` directive — every site shipped by this tool runs HTTP/1.1
over TLS. The phase closes that gap with a one-line directive per
template (or one global directive in the embedded base config,
decided in planning).

The change is operator-invisible: browsers negotiate HTTP/2 via ALPN
on the existing TCP/443. No firewall change. No new CLI flag. No
new operator action beyond `--sync_config` to pick up the new
base-config content.
</domain>

<decisions>
## Implementation Decisions

### Where to emit `http2 on;`

Two valid placements; pick ONE in planning:

| Option | Where | Pros | Cons |
|---|---|---|---|
| A | Inside each per-service SSL template's `server {}` block | Explicit per-vhost; obvious in `--show_template` output | 11 template touches; risk of drift if a new template is added without it |
| B | Once at the `http {}` level in `NGINX_CONF_TEMPLATE` | Single touch; no per-template churn; new templates inherit automatically | Requires `--sync_config` to propagate to existing operators; less visible in template output |

**Default preference:** Option B (single source of truth at the
`http {}` level). Rationale: matches the existing pattern where
`ssl_protocols`, `ssl_ciphers`, and `ssl_session_timeout` live in
`NGINX_CONF_TEMPLATE` rather than per-template. Confirms via the
existing `--verify_config` / `--sync_config` flow.

Planner can override to Option A if testing reveals that not all
operator nginx setups load `NGINX_CONF_TEMPLATE` via `--sync_config`
(some operators may have customised base configs and skipped sync).

### Syntax choice (pre-1.25 vs post-1.25)

nginx 1.25.0 deprecated the `listen ... ssl http2;` form in favour
of a separate `http2 on;` directive. Both still work in current
nginx, but the project's documented base version is 1.24.1 (per
`config_verification.py` headers).

**Decision:** use the post-1.25 `http2 on;` directive. nginx 1.24
supports it via backport in many distros; explicit operator-facing
note in the v1.12 RELEASE_NOTES that nginx ≥ 1.24 is the minimum.

If planning discovers the post-1.25 syntax is not universally
supported on 1.24 (e.g., distro-specific build), fall back to the
legacy form (`listen 443 ssl http2;`) and document the choice.

### Tests

- A unit test asserts that every SSL template's `TEMPLATE` string
  contains either `http2 on` or `listen ... ssl http2` after the
  Phase 2.5 changes land. The test is the regression guard against
  future templates being added without HTTP/2.
- A test on `NGINX_CONF_TEMPLATE` (or `GENERAL_CONF_TEMPLATE`,
  depending on the emit-location decision) asserts the directive
  is present.
- No new integration tests required — the existing template tests
  cover output stability; only the assertion set grows.

### Banner comment correction

The `# incl. SSL/http2 1.24.1` banner in `NGINX_CONF_TEMPLATE`,
`GENERAL_CONF_TEMPLATE`, `SECURITY_CONF_TEMPLATE`, and every
per-service template gets a date refresh as part of the version
bump (existing project convention: bump version + date when
template content changes). The banner now correctly describes the
content.
