<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| embedded template → operator nginx.conf | NGINX_CONF_TEMPLATE content is written to the host filesystem by `--sync_config`; operator must explicitly invoke this to pick up the new directive |
| nginx config parser | The new `http2 on;` directive at `http {}` scope is parsed by nginx on next reload; a typo or wrong scope would cause `nginx -t` to fail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.5-01 | Information Disclosure (gaslighting) | NGINX_CONF_TEMPLATE → operator nginx.conf | mitigate | `--verify_config` already performs SHA256 comparison (config_verification.py lines 199-241); any operator who has not run `--sync_config` will see a diff when they next run `--verify_config`, surfacing the missing directive. The new regression test enforces the directive is present in the embedded template so the diff is guaranteed to appear. Document the `--sync_config` requirement in the v1.12 RELEASE_NOTES (Phase 4 deliverable). |
| T-02.5-02 | Tampering | `http2 on;` directive scope in NGINX_CONF_TEMPLATE | mitigate | Unit test `test_http2_directive_is_in_http_scope` asserts the directive is inside the `http {}` block, not at the wrong level. Operator-side: the post-v1.11.1 `nginx -t`-before-reload gate in `utils.py` catches any config parse errors before nginx reload. |
| T-02.5-SC | Tampering | npm/pip/cargo installs | accept | This plan adds no new dependencies; no package installs occur. |
</threat_model>
