## Deviations from Plan

### Auto-fixed Issue

**[Rule 1 - Bug] Regex assertion instead of literal string match**
- **Found during:** Task 2 verification
- **Issue:** The plan specified `assert "http2 on" in NGINX_CONF_TEMPLATE` (single space), but `NGINX_CONF_TEMPLATE` uses column-aligned whitespace: `http2                  on;`. The literal substring `"http2 on"` is not present in the template, causing both new tests to fail.
- **Fix:** Used `re.search(r'http2\s+on;', ...)` which matches any amount of whitespace between `http2` and `on;`, including the padded variant. This is strictly better — it also requires the semicolon.
- **Files modified:** `tests/test_templates.py`
- **Commit:** `d32c20a` (included in Task 2 commit)

## Deferred Verification (NOT covered by this plan)

**Phase 2.5 ROADMAP success criterion #4** — "A browser request against a v1.12-generated config negotiates `h2` via ALPN" — is explicitly deferred to Phase 4 (v1.12 release-candidate walkthrough). This plan's automated tests verify:
- The directive is present in the embedded template (in-Python string assertion)
- The directive is at the correct `http {}` scope (slice + regex assertion)

What cannot be verified automatically: actual ALPN negotiation between a real browser and a real nginx process. This requires an operator to run `--sync_config`, reload nginx, and verify `curl -I --http2 https://...` returns `HTTP/2 200`. That step is owned by the v1.12 RC process (Phase 4).
