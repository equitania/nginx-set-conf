<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Template content → nginx config | Removing directives changes what nginx loads; must not remove consumer directives |
| Interactive stdin → cert_key | User-supplied cert_key path is passed to execute_commands; existing path validation applies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Denial of Service | Removing proxy_cache_path/limit_req_zone from vhosts that actually use them | mitigate | Confirmed in planning: redirect.py and redirect_ssl.py server blocks contain no proxy_cache or limit_req consumer directives; the declarations were orphaned. Absence tests in Task 1 lock this down. |
| T-03-03-02 | Elevation of Privilege | cert_key prompt accepts arbitrary path input | accept | retrieve_valid_input already enforces 4096-char cap (SEC-04 Phase 1); cert_key path validation in execute_commands/utils.py is unchanged — prompt merely surfaces the existing parameter |
| T-03-03-03 | Information Disclosure | cert_key path echoed in interactive mode | accept | Terminal echo is standard CLI behaviour; the key is not logged or written to any file by the prompt itself |
| T-03-03-04 | Repudiation | Other vhosts rely on shared nginx memory zones declared in redirect templates | accept | proxy_cache_path / limit_req_zone are per-context declarations; nginx resolves them per config file, not globally across conf.d. No other template references the zones declared in redirect.py or redirect_ssl.py |
| T-03-03-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan |

Security posture note: The Phase 2 sentinel-leak guard (COR-02) requires redirect_domain to be
provided before these templates are rendered. That guard lives in validators.py and utils.py and
is not touched by this plan. Stripping the unused shared-memory directives does not affect the
guard — the guard fires before any template substitution occurs.
</threat_model>
