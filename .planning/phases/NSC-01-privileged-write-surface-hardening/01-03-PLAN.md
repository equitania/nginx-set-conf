<objective>
Fix the private key file permission race in `setup_default_server` in `utils.py`:
1. Add a `_restrictive_umask()` context manager that sets `umask(0o077)` and
   restores the old umask in a `finally` block.
2. Wrap the `_run_command(["openssl", ...])` call with this context manager, so
   openssl creates the key file with mode `0o600` directly (no race window exists).
3. Remove the now-redundant `_run_command(["chmod", "600", key_path])` post-hoc
   subprocess call — it communicated the wrong intent (implying the key was
   world-readable until that call) and is now misleading.

Purpose: On Linux/macOS, openssl writes the key file with mode determined by
`0o666 & ~umask`. With the default `umask(0o022)`, the key is briefly `0o644`
(world-readable) between the openssl write and the chmod subprocess. A monitoring
agent reading `/proc/<pid>/fd/` could capture the private key during that window.
Setting `umask(0o077)` around the openssl call eliminates the race atomically.

Output:
- `nginx_set_conf/utils.py` — `_restrictive_umask` context manager added;
  openssl call wrapped; post-hoc chmod removed
- `tests/test_migration.py` — `TestSetupDefaultServer` extended with
  `test_key_file_created_with_mode_600`
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parent process umask → openssl subprocess | os.umask() is inherited by child processes on POSIX — the _restrictive_umask context manager in the parent controls the mode at which openssl creates the key file |
| openssl key write → key_path on filesystem | The key file is visible to other processes from the moment openssl opens it; umask 0o077 ensures it is created at 0o600, eliminating the world-readable window |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Information Disclosure | setup_default_server — private key race window | mitigate | _restrictive_umask(os.umask(0o077)) context wraps openssl call; key file is created at 0o600 by the OS, no post-hoc chmod needed. Regression test uses os.open(mode=0o666) to verify umask is active at creation time. |
| T-01-03-02 | Information Disclosure | Post-hoc chmod 600 implies pre-chmod key was unsafe | mitigate | The post-hoc chmod is removed entirely; intent is now clear — key is born at 0o600. |
| T-01-03-03 | Denial of Service | umask is process-wide; concurrent threads | accept | nginx-set-conf is a single-threaded CLI. Concurrent invocations by multiple operators simultaneously is not a realistic threat. Context manager restores old umask in finally. Residual risk: negligible. |
| T-01-03-SC | Tampering | npm/pip/cargo installs | accept | This plan adds no new dependencies; no package installs occur. |
</threat_model>
